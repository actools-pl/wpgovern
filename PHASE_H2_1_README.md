## Nine blockers closed

### H.2.1-1 — Top-level `local` runtime abort (High)

`local _stack_timeout=120` at the top level of `wpgovern-install.sh` (inside an `if` block, not a function). Under `set -euo pipefail`, `local` outside a function causes a runtime abort. The health-wait loop was never reached.

**Fix:** wrapped in `_wpgovern_stack_wait_healthy()`. All `local` declarations are now inside the function. Verified by scanning `grep -nE '^local ' wpgovern-install.sh` — no results.

### H.2.1-2 — Three services vs four-service contract (High) — THREE SITES

Brief specified four services. Implementation had three (caddy, mariadb, php). Tests drifted to assert three — protecting the buggy implementation rather than the contract.

**Fix — three coordinated sites:**
- `modules/stack/images.sh`: added `wordpress:6.5-apache` to the image list; state fact `stack.images.wordpress_digest`
- `modules/stack/compose.sh`: added `wordpress` service block with healthcheck (`test -f /var/www/html/wp-includes/version.php`), restart policy, and shared bind-mount
- Four bats test files: updated all assertions from "three services" to "four services"

### H.2.1-3 — Caddy cannot serve WordPress static files (High) — TWO SITES

Caddy had `file_server` but no `root` directive and no WordPress docroot mount. CSS/JS/media would all 404 once WordPress is populated in H.4.

**Fix — two coordinated sites:**
- `compose.sh`: added `${install_dir}/wordpress:/var/www/html:ro` mount to Caddy service (read-only — Caddy serves, php/wordpress write)
- `caddyfile.sh`: added `root * /var/www/html` before `php_fastcgi php:9000` (Caddy ordering: `root` establishes the docroot for both `file_server` and `php_fastcgi`)

### H.2.1-4 — Temp file leaks on idempotent no-op (Medium-High) — THREE SITES

When all three generators returned early (hash-match path), `$tmp_file` was not deleted. Files containing DB passwords in plaintext accumulated in `$WPGOVERN_INSTALL_DIR`.

**Fix:** explicit `rm -f "$tmp_file"` at every early-return path in all three generators. No RETURN trap (unreliable in bats setup() context).

### H.2.1-5 — Malformed digest exits before mark_phase_failed (Medium-High)

`extracted="$(echo "$raw_digest" | grep -oE 'sha256:...')"` — under `set -euo pipefail`, grep exits 1 on no match, errexit aborts before `mark_phase_failed`. Same defect class as v53.1→v53.2 Docker GPG fix.

**Fix:** `extracted="$(printf '%s\n' "$raw_digest" | grep -oE 'sha256:[a-f0-9]{64}' || true)"`. The `|| true` prevents errexit from propagating through the command substitution. The subsequent `[[ -z "$extracted" ]]` check is now always reached.

### H.2.1-6 — WPGOVERN_DOMAIN not validated (Medium-High)

Domain values containing Caddyfile-special characters (`{`, `}`, `#`, whitespace) were accepted by the whitelist parser and substituted directly into the Caddyfile. PoC: `example.com { respond "pwn" 200 } #` produced a Caddyfile with an injected block.

**Fix:** RFC 952/1123 hostname regex in `validate_env`:
```
^[A-Za-z0-9]([A-Za-z0-9-]{0,61}[A-Za-z0-9])?(\.[A-Za-z0-9]([A-Za-z0-9-]{0,61}[A-Za-z0-9])?)+$
```
Also added whitespace (`[:space:]`) to the metacharacter rejection in `load_env`.

### H.2.1-7 — Operator-supplied DB passwords break YAML (Medium-High)

Passwords containing `"` or `:` produced malformed YAML. PoC: `MYSQL_ROOT_PASSWORD: "root"bad:pass"` rejects on YAML parse.

**Fix:** `_wpgovern_validate_db_password()` in `validate_env`. Restricts to `^[A-Za-z0-9._@%-]{24,128}$`. Empty passwords are accepted (will be generated by `credentials.sh`). Generator-produced passwords (openssl rand, tr -d '/=+') always pass this check.

### H.2.1-8 — Persisted image digests reused without format validation (Medium)

`images.sh` trusted state values blindly. A malformed value in state produced `image: caddy:2@NOT_A_DIGEST` in `docker-compose.yml`.

**Fix:** validate persisted digest against `^sha256:[a-f0-9]{64}$` before reuse. Uses the same `_wpgovern_is_valid_digest()` helper as the extraction path — single source of truth for the digest format.

### H.2.1-9 — Hand-edited governance files silently overwritten (Medium) — THREE SITES

Generator compared new content vs existing file. Operator modifications caused the old-content comparison to differ (looks like "inputs changed"), triggering a silent overwrite with no warning.

**Fix:** all three generators now read `stack.*.config_sha256` from state (the hash we last wrote) and compare it against the existing file's hash. If they differ, a `WARNING` is logged before overwrite. H.5 will upgrade to fail-closed when governance signing takes over.
